# 三天计划实施与交付状态

更新：2026-10-12。工作候选版本：0.2.0。**新 Runtime 功能已实现并通过 macOS 开发验收；计划整体尚未完成，Windows 实机和客户业务样本仍待验收。**

## 已实现

- 不依赖模型/Planner/Jev 的统一工具入口，MCP stdio（官方 SDK）、CLI JSON、Python SDK。
- 原生窗口观察与动作、窗口截图、无需 OCR 文本的图像像素点击/输入、精确窗口激活与跨进程输入锁。
- trusted-host Python/Shell/PowerShell/argv 作业，持久作业状态、超时、输出上限、取消进程树，生成代码可调用委派 SDK。
- 每会话持久 Playwright worker、获准 origin、Browser 操作/观察。
- 独立本地审批入口、申请/批准/拒绝/撤销/过期/使用记录、请求与代码哈希绑定、重复请求不再次派发。
- SQLite 操作事件、可信 OS 身份、父子操作关联、实时跟随、条件查询、操作/耗时/审批统计、JSONL/CSV 导出、artifact 访问与独立文件/CSV 检查。
- Windows/macOS 安装启动脚本、默认拒绝的策略模板、SDK/生成代码示例、可重复验收脚本。

跨环境共享进度、完成度及待办见 [公共进度目录](progress/README.md)。当前聚焦 macOS，Windows 可由另一台电脑上的 Agent 接续；2026-10-11 已使用此前保存的私有凭据成功登录测试 VM，登录阻塞解除。

接口与使用说明：[Runtime 指南](RUNTIME-GUIDE.md)。原实施目标：[三天计划](PLAN-REPOSITIONING.md)。

## 三种实际 Harness 开发验收

用户指定当前 Codex、当前系统 Hermes、DeepSeek Harness。选定路径覆盖 **3/3**（每种一份完整样本）：Codex 当前会话通过官方 MCP stdio client bridge 直接原生/代码调用；Hermes 和 DeepSeek 经 MCP code.run → 委派 SDK 原生动作。后两者均使用 Hermes 现有 OpenRouter GLM 5.3 Flash 路由，凭据仅在内存/进程环境中使用。

全部路径有 fixture 业务 JSON 与 CSV 独立核验、两项 consumed 审批、completed job、artifact/audit/metrics；SDK 子请求有父操作关联。MCP 会话 schema 的必填字段已修复，回归仍为 550/550。实际版本与全部失败轮次见 [证据](evidence/2026-10-12-harness/README.md)。Codex CLI 当前模型不兼容、DeepSeek 直接逐模型回合原生过期失败、Hermes 原生复验业务完成但 CLI exit 1 单列保留；不能用组合路径成功覆盖这些限制。审批是精确请求的独立 fixture 管理员自动批准，客户人工审批耗时未验收。
