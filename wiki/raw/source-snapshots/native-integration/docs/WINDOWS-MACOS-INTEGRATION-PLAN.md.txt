# Windows / macOS 三项功能整合计划

日期：2026-10-18。状态：**已执行首版开发和自动检查；两端完整实机 / 安装包验收尚未完成。** 最新结果见[实施报告](WINDOWS-MACOS-INTEGRATION-RESULTS.md)。 源码基线为 `262cad6085e8ec1754671f627f048181b1616e5c`；沿用[源码复核报告](WINDOWS-MCP-COMPARISON.md)固定的 Windows-MCP 提交及 xa11y 0.15.0 来源。

本计划只包含：读取过程中的预算限制、现有 Chrome / Edge 网页内容整理、用户操作时暂停 AI 桌面操作。正常路径继续使用 UIA / AX，不要求截图，不扩大浏览器范围。

## 1. 可行性和收益判断

| 功能 | Windows | macOS | 能确定的变化 | 现在不能承诺的结果 |
|---|---|---|---|---|
| 精确窗口读取和读取预算 | 可行；先修正过滤发生太晚，再增加遍历预算 | 可行；已有部分窗口过滤、时间及节点限制，需统一两次读取的预算 | 减少无关窗口正文读取；读取不完整时明确报告 | 所有软件更快、任务成功率提高多少 |
| Chrome / Edge 网页内容整理 | 可行；识别 UIA 网页区域并保留原始目标 ref | 可行但需平台适配；通过 AXWebArea 等可访问性信息识别网页区域 | 让模型看到更有针对性的文字、控件和上下文 | 读到浏览器未暴露的信息、所有网页都能完整读取 |
| 用户接管 | 可行；独立监测服务和派发前检查 | 可行但必须验证输入监听权限、事件来源和辅助进程行为 | 用户操作后暂停后续桌面写入，保留任务状态及已有结果 | 已入系统队列的输入可撤回、正在执行的原生调用可立即打断 |

**三项不能用同一个提升百分比表示。** 第一项主要减少读取工作；第二项主要减少无关输出；第三项主要减少输入冲突，不以加快任务为目标。接管监测还会增加少量常驻开销及恢复步骤。

macOS 不会自动获得与 Windows 相同的收益。当前 `_app_tree` 已对 macOS 设置观察截止时间和按标题过滤；`MacAX.annotate` 另有15秒截止、4096个唯一节点、16384次访问和深度限制。因此 Windows 的窗口过滤问题在 macOS 上已有部分处理，macOS 重点是避免两次遍历各自消耗预算、限制大树读取并适配网页区域。[通用遍历](../src/bokkio/xa11y_backend.py#L405)、[Mac 补充遍历](../src/bokkio/macos_ax.py#L181)

## 2. 提升多少：测量方法和条件示例

开发前为每项保留旧版结果；每个平台、每个功能分别报告：

- **读取**：实际访问节点数、provider 调用数、原生读取 / 补充读取 / 整理输出各自耗时，以及完整任务耗时的中位数和 P95。访问节点数与 provider 调用数分开，不能认为一次访问等于一次系统调用。
- **网页整理**：预先列出的必需事实和控件是否完整；输出字节数；调用方模型能提供实际 token / 费用时再记录，不能用字符数冒充 token。
- **接管**：从监听器收到用户事件到确认暂停的延迟、误暂停、漏暂停、接管后新派发批次、已有队列输入，以及恢复后的重复动作。
- **任务结果**：原任务要求是否完成、独立读回 / 保存重开是否通过，及所有失败和重试。组件检查通过数不作为业务成功率。

可以提前给出计算关系，不能提前给出实测收益。例如某任务原耗时中40%是原生读取；如果新实现将读取耗时减半，其他时间保持不变，则新耗时为 `60% + 40% / 2 = 80%`，总耗时下降20%。**这只是条件计算，40%和减半均非当前项目的测量值。**

读取预算也可能降低一次返回的信息量，导致模型需要多次读取；网页整理可能只减少输出，不减少底层读取。因此最终必须比较完整任务的耗时、费用和成功率。

## 3. 共用设计和兼容范围

三项接入现有 `Runtime.call`、`desktop.observe`、`desktop.act/input`、`desktop.step`、Workflow 和操作记录。新增代码分别负责读取预算、网页输出整理和本机输入监测；Windows / macOS 保留各自原生实现。能力逐项启用，以便比较和回退，不把三个改动同时默认开启。

计划中的接口字段及状态须先更新 `tool_schema.py`、MCP、CLI、SDK、Desktop 和测试；本文是开发前计划；首版已接入的字段和调用方式以[实施报告](WINDOWS-MACOS-INTEGRATION-RESULTS.md)为准。旧版 `max_nodes` / `max_bytes` 继续表示**返回内容限制**，不悄悄改成读取预算。

受限策略 `Runtime` 与普通 Desktop `LocalRuntime` 的授权和审批默认值保持各自现有行为；接管功能用于协调用户与桌面任务，不替代权限检查。通过 SDK 回调 Core 的子动作受同样检查；直接调用旧 backend 的历史 CLI、任意宿主脚本等不能被宣称已全部纳入。首版支持范围明确为当前 Core / Desktop 路径。

## 4. 功能一：窗口过滤和读取预算

### 开发步骤 A1：Windows 提前选定窗口

1. 先枚举必要的应用和顶层窗口身份，匹配精确窗口，再读取目标窗口正文；不递归其他文档窗口。
2. 保留必要的应用菜单和目标窗口相关对话框。必须处理同名窗口、WinUI 多 HWND、托管控件、应用重启和多个进程，而非简单按标题删树。
3. 顶层身份枚举和目标正文读取分别计数；不宣称“完全不读取其他窗口的任何元数据”。
4. 保持原有 ref 生成顺序和歧义检查。改变遍历范围前必须验证同一目标的 ref、父路径及原生身份仍一致。

涉及 `xa11y_backend.snapshot/_app_tree/_walk`、`windows_uia`，并检查实际锁定依赖的窗口枚举行为。[当前过滤](../src/bokkio/xa11y_backend.py#L114)、[身份生成](../src/bokkio/xa11y_backend.py#L507)

### 开发步骤 A2：在读取过程中执行预算

1. 新增独立的读取预算设置，例如节点访问上限、截止时间和深度；同时限制首次读取和能力补查，不只限制返回数组。
2. 返回实际读取数量、截断原因及完整性。未遍历完整时，总节点数未知，不能把已读数量标成总数，也不能把未读到解释成不存在。
3. 第一版部分读取只用于观察；**部分树不直接批准动作**。`desktop.act` / `desktop.input` / Jev / Workflow 必须取得完整的精确操作范围并执行原有重新定位与比较；无法完成读取时返回明确原因并保持零派发。当前完整快照比较不能直接换成对截断树的比较。
4. 调用方收到不完整结果时，可请求更具体的已支持范围或在管理员允许的上限内增加读取预算；若仍不能完整读取则停止。新任务的更窄操作范围和目标验证方式需单独实现及验收，不能靠截断绕过歧义检查。
5. A1 的减少无关窗口读取可以同时改善观察与动作；A2 的部分读取首版主要改善只读查询，**不提前承诺大树写操作同样提速**。

现有 xa11y `Element.children()` 会一次返回直接子节点列表；只在 Python 循环里计数，仍可能先读取巨大列表。先测定该成本；若占主导，再增加依赖层分页 / 有界子节点读取，或在本机补充层实现对应能力。不能用 Python 提前退出的结果声称已经限制全部原生读取。[依赖依据](https://pypi.org/project/xa11y/0.15.0/)

时间预算首版在原生调用之间检查；无法保证中断正在阻塞的 UIA / AX 调用。macOS 可复用已有 AX 消息超时。若 Windows 阻塞调用仍是主要故障，再单独评估进程隔离；本计划不以任意终止线程作为解决办法。

### A 的测试和验收

- 合成树：多窗口、同名窗口、深度 / 宽度大树、循环 / 重复节点、消失控件、半途中异常、同名目标位于未读分支。
- A1 必须证明：未访问无关窗口正文，目标 ref 和原生身份不变；菜单、对话框和已有录制回放仍可用。
- A2 必须证明：达到预算后不继续递归或补查；完整性准确；原生批量子节点读取的额外工作单列；任何未完成的歧义验证均不能派发。
- macOS 单独验证主遍历与 `annotate` 的共享预算及菜单补充；不能只限制前一个遍历。
- Windows 用 Notepad 多文档、Explorer 大目录和可控原生大树；macOS 用 TextEdit 多文档、Finder 和可控 Cocoa 大树。真实应用的可见节点数量必须记录，不把屏幕外文件数量当成 UIA / AX 节点数。

## 5. 功能二：现有 Chrome / Edge 网页内容整理

### 开发步骤 B1：只改变输出，先验证信息是否保留

1. 为 `desktop.observe` 增加显式网页视图选项，例如 `view="web"`，默认原生输出不变；只适用于实际识别为 Chrome / Edge 的目标应用及窗口。
2. Windows 识别 UIA 网页区域；macOS 识别 AXWebArea。选择当前目标窗口的网页区域，同时保留当前模态弹窗、文件对话框、页面关联菜单和框架层级；不因为它们在网页区域外就过滤掉。
3. 按网页实际提供的信息返回正文、表单、按钮、链接、表格关系、当前值、选中 / 禁用状态。没有暴露的字段明确缺失，不拼造 DOM、URL 或内容。
4. 显示输出可以压缩结构，但保留原始 ref 和定位上下文；不能重排后生成另一套控件身份。观测中保存原始树及对应完整性，动作继续按原有完整范围重新检查。
5. 未识别、多个网页区域无法确定、读取不完整等情况，明确报告；调用方可显式切回普通原生视图，不自动截图或换浏览器。网页视图的授权仍按现有应用 / 窗口检查，不把它误当成 `browser.*` 的独立浏览器 origin 限制。

第一版在读取后整理，主要期待输出更有针对性；底层耗时可能不变或略增。第二版只有在 B1 完整性通过后，才按 A 的预算设计尝试少读浏览器工具栏等区域，并验证弹窗不会漏读。

当前 xa11y 0.15.0 已能把 AXWebArea 映射为 `web_area`，说明 macOS 有适配入口；**不等于已验证当前 Chrome / Edge 的暴露内容**。需要分别现场读取确认，不能直接照搬 Windows 的角色和属性名称。

### B 的测试和验收

- 固定本地页面：长正文、表单、重名按钮、表格、折叠内容、嵌套页面区域、原生 / 网页弹窗、切标签、导航、加载中状态和未提供可访问性信息的自绘区域。
- 两个平台分别测 Chrome / Edge，相同页面提供同一份必需事实和控件清单；页面切换或弹窗变化后不得沿用旧目标直接写入。
- 固定页面的必需事实和控件必须全部保留；输出不完整需明确标记。表格的行列关系不能为了压缩而丢失。
- 额外固定若干项目实际需要的页面，先保存旧版读取缺口，再比较新版；登录状态由用户现有会话提供，不获取或复制凭据。
- 必需信息同等完整的前提下比较输出字节、实际 token、读取时间和任务完成率。若输出减少来自漏掉必需信息，判失败；若无明确收益，则保留可选、不默认开启。

## 6. 功能三：用户操作时暂停桌面任务

### 开发步骤 C1：建立共用监测和任务暂停流程

1. 新建本机输入监测服务，只记录事件类别、时间、设备 / 来源标识等必要信息，不记录输入的文字或剪贴板内容。不要直接复用会读取控件内容的录制回调。
2. Windows 使用独立线程接收低级输入 / Raw Input；macOS 使用 session 层的只读 CGEventTap。回调只传递必要事件，不读取 UIA / AX，不等待数据库和界面响应。[Windows 官方约束](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)、[macOS 接口](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:))
3. 所有 Bokkio 输入来源增加一致的自有事件标识：Windows `dwExtraInfo`，macOS `eventSourceUserData`，覆盖输入、像素辅助进程及错误清理路径。结合系统注入标志判断来源；不把“所有注入事件”一概当作自身输入。来源不明按干扰处理，并记录误暂停供分析。[Windows 事件信息](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-kbdllhookstruct)、[macOS 自定义来源字段](https://developer.apple.com/documentation/coregraphics/cgeventfield/eventsourceuserdata)
4. 监测状态由同一 OS 用户、同一交互桌面的进程共用，供 Desktop 服务、MCP 子进程、Workflow 和原生辅助进程读取。不能只放在某个 Python 实例的内存中；每次恢复使用新的状态版本，旧排队动作不能沿用先前许可。
5. 用户按键、鼠标点击、滚动或超过小幅抖动阈值的移动触发暂停；阈值在实机测试后冻结。首版只暂停 AI，**不拦截或吞掉用户输入**。
6. 默认由用户点击“继续”恢复；先重新读取、检查焦点与目标、核对上次动作结果，再决定下一步。自动空闲恢复不进入首版，避免用户停顿时突然恢复操作。

### 开发步骤 C2：覆盖真实派发位置和恢复

1. `Runtime._native_call` 执行动作前检查，`desktop.input` / `desktop.pixel` 在每个有界事件批次前检查；`desktop.activate` / `desktop.launch` 及 Workflow 子动作也要检查。Jev 网络请求返回后、派发前再次检查，避免用户已接管但旧决策随后执行。
2. 原生 Pattern / AX 写入不一定发送系统输入，仍必须在调用前受任务暂停控制；不能只拦 `SendInput` / `CGEvent.post`。
3. 已按下的 AI 按键 / 鼠标按钮应尽力释放，但不能错误释放用户随后按住的相同键；以自有来源和已派发记录区分，实机验证重叠情况。
4. 接管前未派发的请求按零派发记录；可能已有副作用的请求保留 `completion_unknown` 或已有回执。恢复时不得把结果未知的操作清零、换 ID 后重发。因暂停被拒绝且确认零派发的请求需新观察、新请求，必要时重新审批。
5. Workflow 暂停保留已完成步骤和待验证状态；恢复先验证已派发步骤，不重复输入。后台原生写入也随当前桌面任务暂停；普通读取和非桌面数据处理可继续。
6. 监测权限失效、监听器异常或状态过期时，启用接管功能的任务停止新的桌面写入，保留读取及现有紧急停止；不通过强杀整个应用实现暂停。

当前 Windows 长文字按批发送，macOS Swift 输入器也有分块和取消检查，可增加检查点；但 UIA / AX 同步调用、已入系统队列的事件及已启动外部程序不能保证立即中断。本机任意脚本可以绕开 Core 操作 UI；本功能不承诺拦住所有宿主代码。[Windows 输入](../src/bokkio/anchored_input.py#L103)、[macOS 输入](../src/bokkio/native/macos_input.swift#L56)、[Workflow 检查点](../src/bokkio/runtime_workflow.py#L277)

### macOS 的额外要求

已有录制器采用只读 session CGEventTap，可复用打包及权限提示经验；监测模块需独立实现，只收必要事件。检查输入监听权限、监听器创建 / 被系统禁用、睡眠唤醒及锁屏后的状态；权限由用户在系统设置完成，不依赖静默授权。对安装包自带辅助进程单独验证，不用开发终端权限的成功替代安装包结果。[当前录制器](../src/bokkio/native/macos_record.swift#L152)、[Apple 权限预检查接口](https://developer.apple.com/documentation/coregraphics/cgpreflightlisteneventaccess())

### C 的测试和验收

- 合成并发测试：用户输入先于 / 晚于排队动作、Jev 返回时接管、多个 MCP 实例、服务重启、旧状态重用、队列满及监听器失效。
- 必须证明：确认暂停后不启动新的桌面写入批次；已入队事件与已开始原生调用单列，不能冒充零派发；未知完成的恢复不重复执行。
- 两端实机：普通 / 长文字、修饰键、拖动、滚动、中文输入法、手动切焦点、物理鼠标 / 键盘、后台原生写入、暂停 / 恢复 / 紧急停止，以及录制与监听并存。
- 远程或其他软件注入的输入单独验证；无法区分时暂停，不能声称准确识别所有物理来源。Windows hook 可被系统静默移除，macOS tap 也可能失效，健康检查不能包装成绝对保证。
- 分别报告事件接收到暂停确认的中位数、P95、最大值与误暂停 / 漏暂停。**200毫秒 P95 可作为第一轮交互体验目标，属于待验证的设计目标，不是现有性能，也不覆盖已开始的阻塞调用。** 若达不到则公开原因和数据，不能修改时间起点把监听延迟藏掉。

## 7. 风险、处理和上线条件

| 风险 | 影响 | 控制办法 |
|---|---|---|
| 截断后漏掉重名控件或状态 | 误选目标、误报不存在或完成 | 完整性显式返回；部分树只读；完整操作范围重新验证 |
| 过滤 / 分页改变 ref 或菜单上下文 | 旧观察和录制失效 | 保留原身份策略；覆盖同名窗口、菜单、弹窗、HWND及重启测试 |
| 页面整理漏掉弹窗 / 表格关系 | 模型得到错误上下文 | 原始目标与结构可追溯；必需信息清单逐项对照 |
| 自身输入被当成人工、IME被当成按键按住 | 频繁误暂停或永久暂停 | 所有派发来源统一标记；按平台验证输入法与释放；支持手动继续 |
| 监听器失效、跨进程状态不同步 | 接管后仍有新动作 | 共用状态、恢复版本检查、健康失效暂停、原生派发点再次检查 |
| 暂停发生在半次动作中 | 部分文本、拖动未释放、结果不明 | 有界批次、尽力释放、自有事件记录、保留未知状态及独立核对 |
| 增加权限和辅助进程 | 安装包可用性下降 | 功能开关、明确权限状态、两端安装包实测；不将监听授权变成普通只读任务的要求 |
| provider / 系统调用阻塞 | 读取和暂停延迟不能受控 | 分开统计阻塞耗时；协作截止与原生超时；必要时另做隔离设计 |

读取预算和网页整理不应降低既有目标身份、参数、权限及重复请求检查；接管功能默认等待手动恢复。新功能的任一平台尚未通过时，该平台保持未启用或清楚标明试用范围，不能用另一平台结果填分。

## 8. 开发顺序、测试包和交付物

| 阶段 | 开发产物 | 测试与完成条件 |
|---|---|---|
| P0 基线 | 固定源码 / 依赖 / 安装包；增加分阶段计时及实际读取计数；冻结专用用例和判定方法 | 两端保存旧版数据；读取、网页、接管各自建立分母；不重启已暂停的旧业务套件 |
| P1 窗口范围 | A1 提前选择 Windows 窗口；macOS 同范围回归 | 无关正文零访问，ref与结果一致；菜单/弹窗、两端录制回放通过 |
| P2 读取预算 | A2 主遍历和补查共享预算、完整性结果、调用方处理 | 大树、平面列表、重复目标、不完整动作拒绝；需要时单独交付依赖层有界读取 |
| P3 网页输出 | B1 Windows / macOS 内容识别与模型输出整理 | Chrome / Edge 固定页面必需信息全部保留；缺口与实际输出收益逐项报告 |
| P4 接管 | C1 / C2 监测服务、所有输入来源标记、派发检查、暂停 / 恢复 UI | 多进程、Jev、原生和前台输入、未知结果恢复、权限 / 监听失效及IME实机验证 |
| P5 安装包验收 | 两端固定包、单项开关、迁移说明、回退方式 | 真实包重复专项；各开关单独及组合运行；不能只以源码测试代替安装包 |

相关既有测试包括 `test_windows_native`、`test_window_scoped_observation`、`test_refs`、`test_runtime`、`test_desktop_decision`、`test_runtime_workflow`、`test_desktop_operation_recording`、输入和传输测试；新增测试只围绕实际行为、并发和失败恢复，不以镜像实现的断言充数。修改每部分后运行相关测试，最终固定版本运行完整回归和两端新增专项。

真实读取 / 输出性能用例建议每配置预热后交替运行20次，公开每次结果、P50/P95及失败；任务效果测试在开发前冻结每平台的任务清单、次数和独立验收条件，避免看到结果后换题。20次是工程观察样本，不足以证明很低故障率；长时间稳定性和客户环境另行报告。

每阶段保存源码 / 依赖哈希、配置、机器与显示设置、调用方模式、原始结果、首次失败及修复后复测；报告清楚区分开发样本与真实应用。Jev开关两种模式分别比较，模型版本相同；不得将减少一层模型调用当作读取功能收益。

上线依据是：范围与执行检查通过、固定任务不丢必需信息、安装包真实可用，以及该项收益有对应数据。若没有测得收益，记录“未证明收益”并保持可选；不预设总体提速或成功率提高的百分比。
