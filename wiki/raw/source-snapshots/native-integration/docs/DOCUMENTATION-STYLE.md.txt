# 文档用语

技术文档直接说明程序做什么，按具体含义使用以下表述：

- **接口定义**：调用哪个功能，需要哪些参数。
- **参数和权限检查**：参数是否有效，是否允许操作这个应用或资源。
- **执行结果的含义**：动作已发出、结果已确认、执行失败，或者无法确认。
- **重复请求的处理**：同一个操作再次提交时，如何避免重复执行。

测试文档写明检查的具体行为，例如“参数检查测试”“审批测试”“重复请求测试”或“执行结果验证”。保存格式、评分规则、版本绑定和文件哈希也直接使用各自的名称，不另加抽象总称。

保留实际代码标识，例如 `contract_sha256` 和 `office_xlsx_contract.py`，以便读者准确调用或定位。解释这些字段时写明其内容；`contract_sha256` 是接口元数据、实现源码及依赖版本共同计算的 SHA256。

功能存在、测试通过和真实任务完成分别描述。比较外部项目时注明版本、调用路径、证据来源及尚未实测的部分；不从功能数量推导速度、费用、可靠性或任务成功率。
