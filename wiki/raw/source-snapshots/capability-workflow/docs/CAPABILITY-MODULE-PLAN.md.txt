# 轻量能力模块实施计划

日期：2026-10-13。授权：用户要求保存计划并执行。基线：78c3289。

## 目标与边界

保留无模型依赖的 Computer Use Core，增加可选、按需发现的能力模块契约。首轮验证一个 Office 文件模块，复用 Runtime 的授权、精确审批、作业、幂等和审计；目标／任务规划仍属于外部 Harness。完整自主业务矩阵继续保持用户要求的暂停状态。

首个模块选择 `office.xlsx`：对磁盘上的普通 `.xlsx` 提供有界范围读取、另存更新和独立读回核验。使用可选 openpyxl 依赖；不操作正在打开的 Excel／Numbers，不承诺公式重算、复杂格式无损或宏文件支持。更新仅写到新路径，不覆盖源文件或既有文件。

## 执行顺序

1. **执行事实修复**：为通用 backend 已确认未派发的禁用目标等拒绝提供结构化事实；保留派发后异常／未知完成的不重发规则。用真实 backend fixture 通过 Runtime 验证，避免只用伪造异常证明分类。
2. **模块契约与发现**：增加本地静态能力清单、模块／能力版本、输入输出、支持范围、依赖健康、授权、前置条件、预期效果和验证／恢复规则。提供摘要发现、精确详情和精确调用。管理员允许列表控制启用，无动态任意代码导入、在线安装、语义向量搜索或热升级。
3. **Office 垂直闭环**：实现 xlsx 读取／更新／核验，通过现有 code job 执行；包含能力与实现版本、operation/job 关联、文件哈希和核验结果。源文件绑定 SHA256，新产物重新打开核对；不把进程退出成功当作业务核验。
4. **验证与记录**：测试禁用模块、缺失依赖、不兼容版本、越权路径、精确审批、重复操作、未知完成，以及输入保留和独立产物核验。验证 MCP／CLI／SDK 共用接口定义和执行结果格式。记录受控样本的通用工具与模块调用对照，只报告本次接口与文件实测，不填入旧自主业务分数。
5. **交付文档**：更新用法、当前进度和结构化状态，保存测试结果和支持边界；不扩大为三层 Agent／世界模型／插件平台。

## 完成标准

- Harness 可以仅先读取模块摘要，再按 capability ID 获取完整接口定义和调用。
- 默认关闭；授权、依赖或版本不满足时零派发，错误可解释。
- 更新请求绑定源哈希与新输出路径，同 operation ID 不重复写入；未知执行结果不自动切换实现。
- Office 样本实际生成并读回 `.xlsx`，核验目标单元格和源哈希；至少包含篡改／已有输出等反例。
- 针对性测试及适用的隔离回归通过；本轮未运行的客户／Windows／完整业务验收明确列为未验收。
