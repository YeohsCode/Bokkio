## 已交付

配置、对话、录制、Shortcuts 编辑与维护共四个入口，复用同一份 Workflow 数据。录制保存 WebM 视频及结构化步骤；回放使用控件身份、窗口上下文、相对输入点或窗口内图像锚点。窗口位置变化后重新解析目标，不沿用录制时的绝对坐标。

编辑器提供视频与步骤定位、多选、复制、删除、拖动重排、停用、撤销/重做、参数、速度、重复、断点、单步、运行回执、版本恢复、归档恢复、片段重录和当前位置修复。执行过但检查失败的步骤，修复后只重查结果，不重复派发动作。

对话调用 DeepSeek Harness SDK 的原有任务循环，通过 Bokkio MCP 操作应用。录制和确定性回放不调用旧 Planner/Jev；高层 Planner、Jev、Driver 三层旧路径保留。桌面入口默认本机直接执行，不新增逐步审批。

主窗口在录制和前台回放时隐藏；录制浮条、托盘及全局快捷键负责控制，暂停/结束回放会恢复主窗口。紧急停止为 Ctrl/⌘+Shift+F12，暂停为 Ctrl/⌘+Shift+P，录制/结束为 Ctrl/⌘+Shift+R。配置页显示按键注册失败。

## 实测暴露并修复的问题

- 无语义画布只暴露 focus 时，点击不再被降级成聚焦；保留相对输入点。刷新应用会剔除已经退出的 PID；屏幕来源按本应用窗口 ID 排除，避免误删名称以 Bokkio 开头的其他应用窗口。
- Windows Ctrl+Shift+Esc 被系统占用，原紧急停止快捷键失效。改用 Ctrl/⌘+Shift+F12，增加注册结果显示。
- 停止录制后，晚返回的录制轮询可能把界面恢复为“录制中”，导致回放按钮保持禁用。用轮询代次丢弃过期响应，并将快捷控制改为主进程读取实际状态、串行处理；捕获器生命周期操作也串行化。
- SDK 已返回结果但进程仍在收尾时，界面过早允许下一任务；子进程持有输出管道还会延迟 EOF。现在结果到达后等待 SDK 进程结束，任务终态不依赖后代管道 EOF；新增真实子进程合同回归。
- 取消 SDK 进程树过早，会杀死代码作业的工作进程，使作业留在 running。现在先标记任务停止、拒绝该任务新建会话、关闭会话并取消作业，等待工作进程持久化回执，再结束 SDK；旧丢失工作进程由既有 unknown 路径核对。
- Windows SDK 在 ARM64 guest 中自动寻找不存在的 ARM64 runtime。打包并明确调用官方 x64 SDK，使用系统 x64 仿真；Electron 仍为 ARM64。
- macOS 激活应用后 NSWorkspace 的前台状态缓存不更新，导致输入前守卫拒绝。通过原生 RunLoop 刷新，并核验目标窗口和输入焦点。
- 中文输入、标题变化后的文本读回、VM 键盘重复、WebM 无限 duration、进程组清理异常、草稿视频关联均已修复并复测。
- 自动化脚本在隐藏窗口上默认按动画帧等待，会超时；Windows 界面测试改用固定轮询并以实际全局快捷键控制录制。该脚本问题与录制状态竞态分别保留，不混算。Playwright 此版本的 waitForFunction 把异步谓词返回的 Promise 当作已满足；改为 Node 端逐次 await API，重跑 Windows 整链和停止检查。模型曾漏掉测试代码中的 sleep，已将该次记录为失败；最终以明确代码、真实作业请求和数据库回执评分。

## 实际应用覆盖差距

已直接验证 TextEdit 和 Windows Notepad；文本与稳定控件已覆盖，瞬间消失/重排的控件、菜单/对话框、虚拟列表及 GUI 文件保存还需实际应用对照。图像锚点及修复的独立计数验证使用自有 Cocoa fixture。Finder/Explorer、Excel、Feishu、Safari/Edge 的 30 次基础录制回放矩阵、小时级录制、第二物理显示器、签名发布与自动更新尚未完成。原完整业务矩阵继续保持用户要求的暂停状态。
