## 已定位并修复

- **Core 通用几何读取：** Numbers 暴露非有限坐标导致整个 AX 观察失败。现在保留节点的可读值，将无效几何标记为不可见并禁止派发；原生补充层同样拒绝非有限矩形。没有新增 Numbers 业务分支。真实 Numbers 表格读取已恢复，7 个几何／零派发反例通过。
- **预检与重新打开：** 多个同名进程按实际拥有目标窗口的 PID 绑定；正确处理错误字符串；等待应用注册。新进程使用进程级不恢复旧窗口的参数，不关闭包含用户其他文档的进程。
- **判定器：** 正确识别空单元格；按 Summary/Actions/Invoices 中的事实与金额关联判定，不要求目标未规定的 Owner 标签样式。Appendix 必须原样。报告总额可放在任一章节。14 个业务／UI／重评分反例通过。
- **Harness 环境：** r2 新数据目录安装超时，r3 复制的 Hermes 环境保留绝对路径导致启动失败；r4 使用原有自建隔离运行时完成四题实际启动。未修改用户原配置。启动／安装成本未从墙钟中扣掉。

尚未解决的真实执行问题：首轮 Hermes/DeepSeek T01 的激活出现未知完成（同一 Core 请求没有以新 ID 盲重发，见[诊断](unknown-replay-diagnostics.json)）；Hermes 跨应用报告出现[负责人事实错误](r4-owner-diagnostics.json)；两种调用方的 Preview 验证流程有超时／超回合。DeepSeek 跨应用过程中选择 AppleScript 读回曾遇到权限／超时，随后恢复并完成；不计为自动获得 OS 权限。
