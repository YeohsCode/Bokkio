# Bokkio 桌面 UX 与操作录制回放计划

2026-10-15，r6。按用户纠正：Shortcuts 的录制是记录应用操作并生成 Workflow，回放是重新执行操作。r3 中加入录像、播放器和视频时间线的设计已撤回。本文件为当前方案。

## 1. 架构与开源参考

使用 Electron + React/TypeScript 承载 macOS 和 Windows 的同一套界面；已有 Python Runtime 和平台适配器负责系统能力。安装后由 Dock/开始菜单启动，Electron 自动启动 Runtime、管理全局快捷键、录制浮条和托盘。普通网页无法承担系统输入监听和 AX/UIA 查询，因此界面装在桌面宿主内。禁止 Java/JVM。

不整合三个开源录制引擎。参考 CrossMacro 的步骤列表、属性编辑和回放控制，KeymouseGo 的快捷录制操作，Ui.Vision 的断点、单步和日志；实现保持一份 Workflow 模型和已有驱动。把三个项目拼接起来会重复捕获事件、引入不同的步骤语义和窗口坐标体系，实际收益不足。

Electron 代价是安装体积、内存以及分平台 Python/SDK 打包。macOS 和 Windows 共用界面、IPC 和 Workflow schema，分别连接 Swift CGEventTap/AX 与 Windows ctypes Hooks/UIA。跨系统复用需要重新绑定应用和控件。

## 2. 四个入口的职责

| 入口 | 当前交互 |
|---|---|
| 配置 | 模型地址、模型、系统加密 API Key、连接测试、工作目录、运行环境、辅助功能/输入监控入口、全局快捷键状态 |
| 对话 | 任务输入、历史、SDK 工具执行进度、结果、停止；通过 MCP 调用已有 Workflow |
| 操作录制 | 选择应用、开始/暂停/继续/停止、浮条与托盘、实时步骤和无法识别操作提示；停止后打开草稿 |
| Shortcuts 维护与回放 | 左侧流程库，中间步骤表，右侧目标/内容/验证，底部日志、参数、运行记录和版本；多选、复制、删除、重排、停用、撤销/重做、补录、归档恢复；速度/次数、断点/单步/继续、失败检查与修复 |

主要旅程：选择应用 → 演示操作 → 停止 → 检查目标、内容和问题 → 保存版本 → 从明确初始状态回放 → 独立验证应用结果。维护从失败步骤进入，修改目标/参数/等待/检查或补录选中连续步骤，再生成新版本。

步骤表是编辑中心。控件角色、名称、稳定标识、父级路径、窗口身份、相对输入点和必要的图像锚点用于理解和定位步骤。图像锚点是按需截取控件区域；不启动视频流。

## 3. 操作录制的细节

macOS 原生助手监听 CGEventTap，并读取 AX 控件和窗口上下文。Windows 捕获进程使用低层键鼠 Hook，独立 COM/UIA 线程查询目标。选中应用之外的操作、Bokkio 自己的界面和控制热键不编入步骤。

产物是带顺序、相对时间、应用身份、窗口上下文、目标选择器、动作和参数的 v2 Workflow。文本编辑归并为最终值步骤，组合键保留为组合键；输入控件允许 focus，画布不能用 focus 替代点击。原生动作不适用时保存控件/窗口相对输入点。

每次捕获持久化草稿。暂停停止监听并刷新待处理输入，继续启动监听并扣除暂停时间，停止结束捕获并关闭会话。按钮、托盘和全局控制共享串行生命周期。没有捕获到目标的操作显示为问题，不能当作成功步骤。

短暂菜单、弹窗和快速变化目标仍是实测重点：点击后重新读取的树可能已经变化，当前链路尚未证明对这些目标普遍可靠。这是录制质量问题，移除视频不会解决它。

## 4. 回放细节与三层规划

按步骤重新绑定应用和窗口，获取新观察，解析控件身份/父级上下文；图像目标在当前窗口找图，相对点按当前范围计算。使用原生动作或系统输入执行，等待并检查完成条件，保存实际回执。操作时间戳保留，回放按间隔和速度执行；它不是视频播放时间。

断点在动作前暂停，单步产生一个持久检查点。已派发但验证失败的步骤修复后只重新检查，避免再次点击/提交；完成结果未知的步骤不能自动重发。后台模式只支持能独立验证的原生值操作，普通键鼠步骤使用前台模式。

原 Planner/Jev/Driver 三层规划不参与确定性 Workflow 的录制和回放；本次修正不改变该分工。驱动、回执和验证能力继续复用。对话继续使用已有 DeepSeek Harness SDK，经 MCP 调用 Runtime；不另造 agent loop。

本机直接执行沿用当前 LocalRuntime 默认，不增加逐步审批。系统辅助功能/输入监听仍由操作系统提供。图像定位的截取能力单独需要屏幕采集授权，普通操作录制不依赖它。

## 5. 本次修正的副作用评估与处理

| 耦合/副作用 | 修正 |
|---|---|
| 录制启动先枚举屏幕源、申请视频流 | 移除源选择与采集 IPC，直接启动操作捕获器 |
| 暂停/停止等待视频流与封装，失败可能遮住已捕获步骤 | 生命周期只管理操作进程、草稿、浮条和窗口 |
| 播放器和时间线占据维护界面 | 移除，步骤表作为主要工作区 |
| 误删操作时间戳会改变回放间隔 | 保留 recorded_at 和回放速度/间隔逻辑 |
| 视频数据模型残留 | 从步骤与录制元数据中移除视频字段，不保留兼容分支 |
| 视频专属测试 | 删除编码、播放器和时长测试；实际录制测试验证操作步骤和独立回放结果 |
| 重录按钮与快捷键停止走不同分支 | 统一合并函数，保存原 Workflow 身份、断点与可撤销修改 |
| 重复补录覆盖应用别名、时间戳影响前后间隔 | 生成不冲突别名；将补录时间平移至原片段起点，调整后续时间 |
| 空补录或非连续选择误删步骤 | 保留原步骤并给出修复提示 |

不建设录像审阅能力。动作捕获、控件定位和自动执行由操作录制链路直接完成。目标属性、执行回执与独立结果检查继续承担流程维护和验证；图像锚点继续承担视觉定位。

## 6. 验证与后续工作

本次专项必须检查：屏幕采集接口不可用时仍能完成操作录制；暂停期间的操作不进入步骤；真实热键停止；无视频文件/隐藏采集窗口；编辑与保存；按钮/热键补录合并；清空目标后真实回放并独立读回；数据模型中不存在视频字段；中断草稿恢复。

macOS 和 Windows 分别测试；合成模型测试与真实 GUI 结果分别报告。历史 TextEdit/Notepad 的成功不能代替 Finder/Explorer、Excel、飞书、Safari/Edge 中的菜单、弹窗、虚拟列表和实际保存验证。原完整业务矩阵仍维持用户要求的暂停。

当前专项结果见 [操作录制修正报告](evidence/2026-10-15-operation-recording/README.md)。后续产品工作仍包括真实应用矩阵、不同显示缩放/输入法，以及签名发布/更新。

## 7. 分层实时日志

对话的新原生 UI 操作使用“全局规划 Harness → 局部决策 Jev → Runtime 执行/读回”，其他工具标为 Harness 编排；Shortcuts 使用“Workflow → 固定步骤 → 执行/验证”。Jev 参与情况从实际调用事件统计。实际调用关系、数据关联和验收见[决策分工与实时日志](DECISION-LAYERS.md)。

## Jev 接线修正

桌面对话已使用 desktop.step 接通 Harness → Jev → Runtime。配置提供 Jev 服务/模型/独立 Key，实时日志从实际 Jev 审计事件形成 L2 节点；纯读取和固定回放保持零次 Jev。模型返回后刷新观察并比较语义树，避免过期或变更的 UI 被继续操作。详见[实际决策链路](DECISION-LAYERS.md)。

## Jev 可选模式与自定义服务

配置页新增默认开启的 Jev 开关、完整 API URL、任意模型名称和独立系统加密 Key。保存后对新任务生效，历史和正在运行任务保留启动模式。关闭时 Harness 选择原生动作/目标，直接调用 Runtime；开启时仍由 Jev 局部决策，日志分别标明真实引擎。自定义地址遵循 Jev Decisions 协议，loopback 直连；不自动向新地址转发其他服务密钥。
