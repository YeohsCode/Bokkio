# P5 续测：规划观察、恢复与检查点

本轮继续使用原生 Accessibility/UIA 操作。浏览器兼容性、真正的虚拟化 provider 和更广的独立应用集仍是后续工作。

## 实现变化

### 规划观察覆盖

旧版对每个应用只取前 100 个节点，可能遗漏大树后面的目标或后面的窗口。新版最多向规划器提供 240 个节点：

- 目标提到的原生名称优先，保留同名候选、父级与窗口上下文。
- 保留小范围相邻控件，让规划器能看到 Search 旁的 Submit，即使用户没有直接提到按钮名称。
- 补充最多 32 个状态标签。没有名称命中时，在各窗口之间分配预算，并在各自节点序列中均匀抽样。
- 明确报告观察策略、原始数量、保留数量和省略数量。没有进入观察的控件不能据此被判定不存在。

这是有界的观察抽样，不能保证任意未命名目标都被覆盖。Jev 决策仍由实际原生树生成；执行前完整范围的快照检查继续保留。规划目标带上父容器名称时，如果已有可原生点击的命名目标，未明确要求的滚动候选会被移除；显式滚动请求仍保留。

### 恢复与持久化

- 子任务窗口读取失败现在进入同一套有预算限制的重规划，规划器重新获得当前窗口列表。重规划收到已验证子任务的目标与成功条件，不能只凭不透明的步骤 ID 猜测进度。
- Windows 临时文件占用导致原子替换失败时，最多尝试六次，总等待最多 1.55 秒。其他磁盘错误立即停止。
- 运行中如果连失败状态都无法持久化，返回内存中的 `failed` 与 `checkpoint_error`，停止派发后续动作。初始检查点无法写入时直接抛出配置/存储错误。
- macOS 原生树中再次出现同名、同 PID 的根 application 节点时立即报错。不会将异常节点跳过并冒充可执行的完整树。

## 验证

五项续测的最终结果均通过。恢复、暂停与重启来自修正后的第二轮；七步流程和相邻控件来自随后更新观察与候选动作后的最终轮。这不是单次运行的通用准确率评估。完整记录见 [本轮证据](evidence/2026-10-02-p5-followup/README.md)。

| 任务 | 派发尝试 | 重规划 | 独立原生结果 | 端到端秒数 |
| --- | --- | --- | --- | --- |
| 七步、三应用流程，含 1,000 按钮树 | 7 | 0 | 目标、按钮状态及动作顺序通过 | 131.544 |
| 两次连续原生状态变化 | 4 | 2 | 两次旧决策拒绝，输入与提交通过 | 234.940 |

七步流程的规划器从 1,015 节点中保留 13 个节点；相邻控件流程从 2,081 节点中保留 55 个节点。执行前仍读取完整范围，检查旧快照。耗时包含原生观察、模型等待、执行与检查点写入；这组小样本还不足以解释各项开销或估计一般任务可靠性。

最终 macOS 与 Windows 隔离回归均为 **111 项通过**。窗口改名后恢复、已完成子任务进入重规划、观察抽样上限和跨进程 application 节点识别由隔离回归覆盖。真实恢复/暂停/重启证据产生于相邻控件与进度上下文补充前；最终轮另验证了更新后的完整七步流程及相邻控件发现。

真实 Windows 文件锁测试已通过：独立的读取句柄占用测试文件 150 毫秒，原子替换在句柄释放后成功，最终内容为新版。隔离测试还检查了永久占用的尝试上限、规划器返回后写入失败时不执行动作，以及大树中的第 997 个目标。

首轮扩展流程执行了七个原生动作，但最终检查点写入失败，不能记为完整成功。失败与运行中复制 trace 的时间重合；目前无法确定唯一根因。已保留当时的检查点与错误日志，并以真实 Windows 句柄占用复现和验证有限重试。后续完整证据在任务完成后复制；必要的运行中诊断改用允许原子替换的共享读取句柄。

第二轮七步流程在 Sample 619 处低置信度拒绝：目标描述带有父容器 Scale content，导致额外滚动选项分散决策；随后重规划输出截断，任务返回 failed。有限上下文中的候选过滤已修正，最终轮七步流程通过；原始失败记录继续保留。置信度门槛仍为 0.7，截断输出仍拒绝。

## macOS 当时限制

系统会话标志仍显示屏幕锁定。权限已经授予，但两套新建 Cocoa fixture 的原生树仍返回嵌套 application；Search/Submit 无法读取，因此没有派发输入或点击。新预检查明确记录原生错误，不再仅因前台名为 loginwindow 就停止。

这是 macOS 当前实机验收的限制，代码开发、隔离测试和 Windows 实机测试均可继续。根因仍需解锁后的对照结果；本轮不将错误诊断当作 macOS 操作测试通过。

2026-10-06 已恢复原生读取并完成双轴滚动、三条模型跨应用任务及 Workflow 对照；原始失败记录保留，见 [Mac 续测](MACOS-FOLLOWUP.md)。

## 复现命令

先启动已构建的 Windows interactions fixture；以下脚本会启动并关闭自身创建的 scale、hard fixture 和新 Notepad。

```powershell
.venv\Scripts\python.exe scripts\verify_p5_extended.py --scale-fixture fixtures\windows-scale\bin\Release\net8.0-windows\bokkio-scale-fixture.exe --hard-fixture fixtures\windows-jev-hard\bin\Release\net8.0-windows\bokkio-jev-hard-fixture.exe --output C:\BokkioTasks\p5-extended
.venv\Scripts\python.exe scripts\verify_p5_neighbor.py --output C:\BokkioTasks\p5-neighbor
```

`--extended-only` 只运行七步流程。脚本中的输入值均写入专用 fixture 与新建 Notepad；不要用用户已有文档替换这些对象。
